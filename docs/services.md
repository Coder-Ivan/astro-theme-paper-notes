# 启用账户、私有日记和评论

默认的静态博客可以直接托管 `dist/`。如果想开放注册、让读者回复文章，或只让获授权的用户读日记，需要在有持久磁盘的主机上运行随主题提供的 Node.js 服务。它在同一个域名下提供公开网页、账户表单、评论接口和受保护的日记，依赖 Node.js 24 的内置 SQLite。

## 在本机试用

1. 在工程根目录安装依赖，把 `theme.config.mjs` 中的 `services` 改为 `true`。
2. 在同一目录运行以下命令。`forest-editor` 是示例站主用户名，你可以用自己的名字替换。请将首次创建时显示的随机密码保存到密码管理器。

```sh
npm ci
npm run build
node server/owner.mjs forest-editor
npm run serve
```

3. 打开终端显示的地址，默认是 `http://127.0.0.1:4321`。从页头登录，到「我的账户」更换初始密码。站主只初始化一次，重启或升级后沿用原有账户数据库。自动化安装也可将密码从自己的秘密存储通过私有管道送给 `node server/owner.mjs forest-editor --password-stdin`。
4. 用另一个浏览器窗口注册读者账号。注册时可以选头像，注册后可在公开文章末尾留言和回复。站主在「我的账户 → 用户管理」将该账号的权限设为「日记读者」，读者即可打开日历、阅读全文并搜索日记。撤销权限后，原会话再次访问日记正文、索引或附件时都会重新校验。

本机联调账户和评论时请使用 `npm run serve` 提供的完整站点。Astro 开发服务用于修改和预览界面。修改内容或样式后，在本机服务终端按 Ctrl+C，重新执行 `npm run build`，成功后再启动 `npm run serve`。

## 用站主账号管理文章

打开「我的账户 → 文章管理」或访问 `/account/posts`。一级笔记本默认展开，二级及更深的笔记本默认收起。点击目录名可独立展开或收起这一支。使用目录上方的「全部展开」或「全部折叠」可一次切换当前列表中的所有目录，「恢复默认」会只展开一级。搜索结果中也可以使用这三个按钮，已有的筛选条件和文章勾选都会保留。每篇文章只出现在直属目录中，目录旁的篇数包含子目录中的文章。没有笔记本路径的文章归入「未分类」。

展开目录后，先看到直属的置顶文章，再看到普通文章，两组各自按标题排序。下方的子目录可以单独展开。搜索标题、目录名或路径（如 `观察手册 / 测量方法`）会展开匹配分支。逐篇保存后会展开上级目录并定位到刚修改的文章。

勾选文章可跨目录选择，勾选目录则选中整棵子树。搜索时，目录全选只包含该分支中匹配的文章。核对已选篇数后，点击「批量显示」「批量隐藏」「批量置顶」或「批量取消置顶」。服务会显示选中数和实际修改数，有效修改会合并到一次构建中。收起目录会保留勾选，切换搜索或提交操作后需重新勾选。

- 「隐藏」会在新构建中撤下公开页面、搜索条目和该文章独占的附件，并立即关闭对应的评论接口。「显示」可恢复原网址和讨论。
- 「置顶」会把文章放到首页列表前面，多篇置顶按原日期排序。「取消置顶」可恢复默认顺序。可以提前为隐藏文章设置置顶。
- 设置保存到站点的 SQLite 数据库。服务会在后台构建，成功后一起切换公开及私有输出；刷新管理页可查看结果。构建失败时会保留上次成功的版本，修复后点击「重新构建」。有 CDN 时，请让公开页面和搜索索引回源验证，或在更新后刷新缓存。

后台构建需要部署完整主题工程、文章源文件、已导入的 Joplin 内容和 npm 依赖，运行服务的用户需要能够写入工程下的 `.astro/`、`dist/`、`dist-private/` 和持久数据目录。首次构建、后续手动构建及服务进程需使用同一个 `PAPER_NOTES_DATA_DIR`。正式运行一个服务实例即可。升级旧站时，沿用原数据目录运行一次 `npm run build` 并重启服务，管理页就能读取完整笔记本路径和已有的置顶设置。

文章改名或移动时应保留原 ID。如果依赖自动生成的 ID，请保留固定的 `slug`；这样可继续沿用站主设置和已有讨论。隐藏文章保留在私有源稿中，源码仓库的可见性也要按内容需要设置。

## 部署到自己的服务器

建议让支持 TLS 的反向代理监听网站域名，将**全部路径**转给 Node 服务。生产环境把 `PUBLIC_ORIGIN` 设为浏览器地址栏中的 HTTPS 源（含非标准端口时写端口，末尾无斜杠），并在代理中保留原始 Host。这个值用于检查写请求来源和生成安全会话 Cookie。域名也应填写到 `theme.config.mjs` 的 `site` 字段内，再构建网页。

以已创建站主的 Linux 主机为例，如果数据库放在 `/srv/paper-notes-data`，初始化站主时也要使用同一 `PAPER_NOTES_DATA_DIR`。该目录须由运行服务的用户读写。

```sh
PUBLIC_ORIGIN=https://notes.example.org \
PAPER_NOTES_DATA_DIR=/srv/paper-notes-data \
HOST=127.0.0.1 PORT=4321 npm run serve
```

例如，Caddy 可以使用以下站点块。将域名换成自己的域名并先完成 DNS 解析。

```caddyfile
notes.example.org {
    reverse_proxy 127.0.0.1:4321
}
```

- **公开输出**在 `dist/`。私有输出在相邻的 `dist-private/`，其中包含日记和评论路由清单。只把 `dist/` 设置为静态托管目录；启用互动功能时由 Node 进程读取两个目录。请勿把工程根、`content/`、`dist-private/` 或数据库目录设置为公开文件服务目录。
- **持久数据**默认在工程根的 `.paper-notes/`。生产环境请使用持久卷，运行一个服务实例，并在更新主题时保留数据库。备份时停止服务，复制整个数据目录，包括存在的 SQLite WAL 文件；还原时使用同一份完整备份。日记源稿和构建配置也应单独保管。
- **访问控制**对日记页面、搜索索引和专用附件逐次执行。若使用 CDN，让 `/account`、`/diary` 和它们的全部子路径直接回源并禁用缓存，转发 Cookie、Origin、Host 和表单 POST 请求。分享同一个附件给公开文章会使该文件的内容可从公开文章下载。
- **文章变更**在新构建生效、服务读取完整的路由清单后同步到评论。保留内容 ID 可在改标题、改网址时沿用讨论。删除文章后，服务会清理这个 ID 对应的全部评论和回复。建议先在单独目录构建成功，再停服、成套替换 `dist/` 和 `dist-private/` 并重启，避免访客在构建中途读到不完整的文件。

敏感日记的源文件应保存在私有工作副本或私有仓库。静态输出隔离和服务鉴权只能保护部署后的访问，公开的源码仓库本身可被任何人查看。

## 核对自己的部署

用访客窗口依次打开一篇公开文章和日记；访客能读文章，日记会引导登录。普通读者可以发表评论；升级为日记读者后再检查日历、图片和搜索。用站主撤销授权并刷新读者页面，可以验证 CDN 和服务端都按新权限处理。要运行随主题附带的账户、回复和删除清理测试，在工程根目录执行 `node --test server/tests/services.test.mjs`。
